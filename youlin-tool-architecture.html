Youlin Campus · Internal Architecture Dossier · Rev 3.1.0

工具调用双平面架构（Dual-Plane Tool Invocation Architecture） runtime: Next.js App Router · AI SDK v7 · DeepSeek(OpenAI-compatible) · Drizzle/PGlite · Vercel Blob

本系统并未采用单一的「模型 → function calling → 工具」直连拓扑。工具能力被切分为两个正交平面： 模型平面（Plane M）把 8 个能力项以 JSON Schema 形态注册进 streamText 的 tools 描述符， 调用权交给模型的 token 级决策；确定性平面（Plane D）把 11 个能力项完全隐藏在模型视野之外， 由规则分类器 + 策略注册表 + 悲观确认闸门组成控制面，按代码路径派发。两个平面的交汇点是一个单点仲裁器 （canUseModel），它决定本次请求是「让模型接管」还是「由模板直接落盘」。

01拓扑总览：七层垂直切片

请求自左向右穿过准入层与传输层，在仲裁层被撕裂为两条互斥的执行路径；两条路径最终收敛到同一批 适配器（Adapter）与同一组外部副作用（Side Effect）。注意 Plane D 位于仲裁层下方且恒定先执行： 它不是模型的「工具」，而是模型的「前置守卫 + 兜底执行器」。

C1单点仲裁

两个平面互斥，裁决权集中在 canUseModel 一个布尔表达式上，无二级路由、无 fallback 回跳。控制流可静态推演。

C2平面 D 前置

引擎先跑后判。即使最终走模型，Plane D 已完成意图归类与槽位抽取，其 evidence 被用作 RAG 上下文注入。

C3同流多源

模型 token、工具轨迹（data-campus-trace）、等待态（data-waiting-status）合并进同一 SSE 流，前端按 part 类型做投影。

02调用权 × 推理性：19 个能力项的正交切分

「走模型 / 不走模型」不是一维属性，而是两个正交维度的叉积：谁发起调用（模型 token 决策 vs 代码路径）， 与 执行体内是否含推理（生成式 / 表征式 vs 纯 IO 与规则）。只有承认这一点，才能解释为什么 searchForum 不在模型的 tools 里、却仍然调用了 generateText。

判据什么叫「走模型」

工程上可操作的判据只有三条：①是否出现在 streamText({ tools })；②执行体内是否出现 generateText/streamText/embed；③失败时是否有确定性替代路径。只有②才是真正的「走模型」，①只决定「谁按扳机」。

陷阱最容易被误判的一项

searchCampus 在 Plane D，看起来「不走模型」，但它的 RAG 检索必须先调 embedding 服务（Ollama 或 OpenAI 兼容 /embeddings），并在建索引时批量嵌入 PDF。它是表征式推理，不是生成式推理。

03Plane M 时序：function calling 的三次越权

模型平面并非「调用一次工具就结束」。工具执行体在返回 tool-result 之前，可能已经向同一 SSE 流写入了 增量文本、创建了数据库记录、甚至发起了第二次模型生成。这三类越权行为（流越权、状态越权、推理越权）构成了 Plane M 的真实复杂度。

越权①流越权

createDocument 在 execute 内直接 dataStream.write()。工具尚未返回，UI 已开始渲染产物骨架 —— 工具对传输层有写权限。

越权②状态越权

requestSuggestions 内部 saveSuggestions()；grabImage 直写 Blob。工具绕过「模型 → 服务层」分层，直接落库。

越权③推理越权

三个文档类工具内部再起 streamText。一次模型调用衍生出「父决策 + 子生成」两级推理，token 计费与错误归因因此不可线性推算。

04Plane D 时序：控制面如何绕过模型按扳机

Plane D 的调用链里没有 streamText。分类器把自然语言压成 8 类离散意图，路由层做指代消解， 策略注册表判定读写属性，最后用 inputSchema.parse() 补上 AI SDK 原本提供的参数校验 —— 这是一种「手工复刻 function calling、但把决策权收回」的设计，代价是正则覆盖率的长期维护。

05确认闸门：14 个状态迁移中的 4 条死路

CampusPending 是本系统唯一带「人类在环（HITL）」语义的表。它用一张表 + 一个部分唯一索引 （WHERE status='pending'）表达「同一会话同一用户至多一个待确认计划」，从而把并发确认、 陈旧计划、重复执行三类故障压缩到数据库约束层面解决。

并发为什么必须是单条 UPDATE

「先 SELECT 再 UPDATE」在双标签页同时点确认时会双重执行。UPDATE … WHERE status='pending' RETURNING 把悲观锁语义压进一条语句，第二个请求命中 0 行 → 返回「当前没有待确认的操作」。

陈旧为什么要 superseded

用户连发两条不同意图时，旧计划若不撤销，晚到的「确认」会执行与当前语境无关的写操作。因此每条新消息前置一条 superseded 更新，早于分类。

07系统不变式：11 条不可违反的约束

以下约束在代码里以断言、类型、SQL 条件、正则或布尔短路的形式存在。破坏任意一条，架构即退化为「一堆能跑的函数」。

  1. 写操作必须二次确认：toolPolicy[name] === "write" 且 confirmed !== true 时，executeTool 直接抛错，不存在绕过分支。
  2. Schema 先行：Plane D 手工调用 inputSchema.parse()，等价复刻 AI SDK 在 Plane M 上的参数校验；未校验的参数不得进入适配器。
  3. 单点裁决：canUseModel 为假时不创建 streamText，回答由模板字符串逐段写入 text-delta。没有「先试模型再回退」的回跳路径。
  4. 确认原子性：抢占靠单条 UPDATE … RETURNING，非法状态迁移在 SQL 层被拒绝（0 行命中即视为无待确认操作）。
  5. 计划时效性：pending 计划超过 30 分钟即不可见（createdAt > now() - interval '30 minutes'），避免隔夜误触。
  6. 计划互斥：部分唯一索引 ON (chatId, userId) WHERE status='pending' 保证同一会话同一用户至多一个待确认计划。
  7. 隐私双向前置：写入模型上下文前 redactModelMessageTexts()；写入论坛正文前 redactPublicText()。命中联系方式且 kind=unknown 时置 suppressModel，直接阻断模型接管。
  8. 降级单调：hasModelProvider() 为假时，模型能力逐级降为规则 / 模板 / 样本数据；功能集合不减，仅质量下降。
  9. 遥测与控制流解耦：report(step) 只写 transient data part，绝不参与分支判断；轨迹缺失不影响业务正确性。
  10. 模型不得自称执行：system prompt 显式禁止「声称执行了未调用的操作」，因为 Plane M 的工具集不含任何校园写能力。
  11. 写工具不出现在 tools 描述符里：campusTools() 的 11 项从不进入 streamText({ tools })。模型即便产生幻觉也无写权限 —— 这是权限边界，不是代码风格。

09术语表

用于对外沟通时维持术语一致性。若对方追问「这跟普通 function calling 有什么区别」，只需回答：我们把一半的工具从模型视野里摘出去了。

双平面仲裁 Dual-Plane Arbitration
同一请求存在两条互斥执行路径，由单一布尔表达式裁决，不存在并行或仲裁争议。
能力项 Capability Descriptor
一个 tool() 实例，包含 name / description / inputSchema / execute 四元组。
控制面 / 数据面
控制面决定「调什么、允不允许调」；数据面负责「实际读写」。Plane D 同时扮演两者。
悲观确认闸门 Pessimistic Gate
写操作在执行前必须获得一次显式人类确认，且确认动作本身是原子的、单次有效的。
语义重排 Semantic Rerank
用生成式模型对候选集排序或挑选子集，替代向量相似度；失败则退回关键词。
表征式推理 Representational Inference
embedding 编码，不生成文本，只产出向量；属于「走模型」但不算「生成式」。
投影式遥测 Projected Telemetry
服务端把内部步骤投影为 data-campus-trace 流事件，前端只做渲染，不参与决策。
降级阶梯 Degradation Ladder
模型 → 规则 → 模板 → 样本数据 的四级单调下降，每级都有确定的替代实现。
意图空间 Intent Space
8 类离散标签：access / repair / card / notice / forum / lost / qa / unknown。
反事实抑制 suppressModel
即使 kind=unknown 本可交给模型，也用布尔标记推翻该决策，用于隐私场景。
计划态 Plan State
写操作的待执行快照（tool + args + description），序列化存于 CampusPending.plan。
越权 Overreach
工具执行体对流、状态或推理层的额外权限，是本架构最主要的复杂来源。
